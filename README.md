# 青囊 QingNang

> **小胰宝社区 · 医学能力资产包**
>
> 把社区积累的医学能力（医学文献 / 临床试验 / 网页搜索 / 病历处理 / 指标追踪 …）打包成**一只可以被任何 AI Agent 直接加载的工具箱**。
>
> 项目定位：社区医学资产的打包与分发。品牌：小胰宝社区。授权：公益开源。

---

## ⚠️ 医学伦理与免责声明（请先读完这段）

1. **本工具不构成医疗建议。** 青囊只做信息检索与整理，不做诊断、不给用药剂量、不替代医生。
2. **你的病情数据只留在你自己的电脑上。** 所有个人资料写入本机 `~/.qingnang/private/`，**永不上传、永不进 git**。
3. **社区只负责技术分发。** 本包提供的是技术工具与公开信息检索能力，**不承担诊疗责任、不做医疗背书**。
4. **遇到急症请立即就医**，不要依赖任何 AI 工具。

> 每条涉及诊疗的回答都会自动附带来源与上述免责。未经医学审校的知识卡会明确标注 `pending-review`。

## 🚀 一键部署（把下面这段直接复制给你的 Agent）

```
请把青囊（QingNang）医学能力包装到当前环境：

1. git clone https://github.com/PancrePal-xiaoyibao/QingNang.git && cd QingNang
2. bash scripts/deploy.sh --mode=source    # 装依赖 + 拉取 MCP + 建立本机画像（幂等，可重复跑）
3. bash scripts/deploy.sh --mode=agent     # 把能力装到你自己（宿主）
4. bash scripts/doctor.sh                  # 逐通道体检，把结果贴回来

不用填任何 API Key 也能用：网页搜索、中文搜索、医学文献、临床试验都是免费通道。
遇到报错按脚本给的中文提示处理，不要跳过任何一步。
```

**部署规范引导**（按顺序，别跳步）：

| 步 | 命令 | 做什么 | 卡住了看哪 |
|---|---|---|---|
| 1 | `git clone ... && cd QingNang` | 拿到资产包 | 网络不通 → 见「故障排查」代理一节 |
| 2 | `deploy.sh --mode=source` | 装依赖、拉 MCP 包、**探测你的机器**（硬件/网络/代理）并生成 `HOST_PROFILE.md` | 缺 node/python → doctor 会告诉你装什么 |
| 3 | `deploy.sh --mode=agent` | 把三个注入文件装到你自己的技能目录 | 不知道自己的宿主类型 → `--host=<claude\|pi\|openclaw\|codex>`，不填则自动探测 |
| 4 | `doctor.sh` | 逐项体检，输出 `✓` / `⬜` / `❌` | `❌` 会带中文修复指引；`⬜` 是选填项，不影响可用 |

**想先试跑不落地？** 加 `--dry-run`：只验证「配置装载 → 通道发现 → 路由选择」，不写任何文件。

```bash
bash scripts/deploy.sh --dry-run
```

## 🧭 这个包是怎么组织的（给想深入了解的人）

```
INJECT.md            ← 主注入：告诉 Agent「有青囊」，并指路
SEARCH_RUNTIME.md    ← 搜索分流表：具体该用哪个通道
HOST_PROFILE.md      ← 你的机器画像：代理在哪、几个核、装了什么
SKILL.md             ← 总体路由与执行流
references/          ← 病种知识卡、指标解读、术语表（按需加载）
mcp-servers/         ← 六个 MCP 的声明与健康检查
scripts/             ← 部署、探测、体检、自检
```

**为什么分三层注入？**

主注入是常驻在 Agent 上下文里的，**越短越好**。所以它只做一件事：说「有搜索能力，去找 `SEARCH_RUNTIME.md`」。具体用哪个工具，放在按需加载的分流表里。这样**新增搜索工具只需改分流表，不动主注入**。

**为什么要有 `HOST_PROFILE.md`？**

因为**代理是部署的第一道门槛**。很多用户卡在「装完了但搜不到东西」，根因是本机需要代理而 Agent 不知道。所以部署时会自动探测你的网络环境，写进这个文件，Agent 一看就知道。

## ❓ 故障排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 搜不到结果 / 超时 | 本机需要代理 | 看 `HOST_PROFILE.md` 的「网络/代理」一节；`deploy.sh` 会自动探测常见代理端口（1080 / 7890 / 7897 / 8118 / 8888） |
| npm 拉包失败 | 安装期需要代理 | `npm --proxy http://127.0.0.1:7890 --https-proxy http://127.0.0.1:7890 install <pkg>`（把地址换成你自己的） |
| 某个通道显示 `❌` | 通道不可用 | `doctor.sh` 会给出中文修复指引，照做即可 |
| `⬜` 是什么意思 | 选填项未配置 | **不是错误，不影响使用** |
| 提示缺 node / python | 运行时缺失 | `doctor.sh` 会给出对应平台的安装命令 |
| Agent 不知道有青囊 | 注入没装到位 | 重跑 `bash scripts/deploy.sh --mode=agent`；确认三个注入文件都在技能目录里 |

**开发者自检：**

```bash
bash scripts/deploy.sh --dry-run    # 只验证链路，不写文件
bash scripts/check.sh               # 聚合自检（清单一致性 + 体积 + 锚点）
```

## 🤝 参与贡献

**我们最需要的不只是代码**——病种知识卡、术语中英对照、FAQ 整理，都是极有价值的贡献。

**提交前必读红线：**

- ❌ **禁止提交任何真实患者数据**：姓名、身份证号、手机号、住院号、报告单原件、影像。
- ✅ 演示数据一律放在 `data/synthetic/`，用造数脚本生成。
- ✅ PR 模板里有「本 PR 不含任何真实患者信息」的勾选项，**必须勾**。
- ✅ 仓库有自动闸门（pre-commit + CI + AI 复审）会拦截敏感信息，**命中即红**。

**准入纪律**：一条新能力要不要进青囊，看四条——医学相关吗？是能力还是应用？许可干净吗？能被 Agent 调用吗？详见 `skills/qingnang/MERGE_CONTRACT.md`。

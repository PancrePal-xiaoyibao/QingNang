# PRD：青囊 QingNang v1 —— 社区医学能力资产包

> **本文件回答三个问题**：谁用、什么场景、什么算成功。
> **素材来源**：母文档 §1/§1.3/§11/§12 + 主人 15 项决策（K1–K15，见 CHANGE §5.3）。

## 0. 一句话定位

**青囊 = 小胰宝社区的医学能力资产包。把社区积累的医学工具与知识，装成一只任何 AI Agent 都能直接加载的工具箱。**

**品牌**：小胰宝社区 · 青囊 ｜ **定位**：社区医学资产的打包与分发 ｜ **许可**：Apache-2.0（公益开源）

## 1. 用户

### 1.1 用户不是"人"，是"Agent"

**这是本 PRD 最重要的一条**（主人决策 K10）：

> 「这个项目本质上是**面对 agent 的开发，不是面对人的**。」

所以验收尺度是：**Agent 能不能高效、正确地调用这套能力**。

但 Agent 背后站着**真实的人**。所以要分两层看：

| 层 | 主体 | 关心什么 |
|---|---|---|
| **直接用户** | **AI Agent**（Claude Code / pi / OpenClaw / Codex / DSH） | 有没有清晰的通道分流表？调用路径短不短？失败时知不知道该降级到哪？ |
| **最终受益者** | **癌症病友及其家属** | 查得准不准？说出处了吗？我的数据安全吗？ |

### 1.2 最终受益者画像（三类）

| # | 是谁 | 处境 | 核心诉求 | 不想要 |
|---|---|---|---|---|
| **U1** | **病友本人** | 刚确诊或治疗中，情绪压力大，医学名词看不懂 | 「我这个指标什么意思」「有没有新药」「有没有能参加的试验」 | 被推销、被吓、被给假希望 |
| **U2** | **家属 / 照护者** | 替病友查资料、跑医院、做决策支持 | 「怎么问医生」「别的病友怎么应对副作用」「报告单怎么看」 | 信息过载、看完还是不知道下一步做什么 |
| **U3** | **社区志愿者 / 开发者** | 想贡献，但不会写代码或没时间 | 「我加一张知识卡要几步」「怎么把社区已有的 skill 并进来」 | 复杂流程、模糊的准入标准 |

### 1.3 用户规模与形态假设

| 项 | 假设 |
|---|---|
| 首批用户 | 小胰宝社区成员（110+ 生态成员）及其服务的病友 |
| 部署形态 | **单个用户在自己电脑上跑**（不是 SaaS，不是多租户） |
| 技术门槛 | **零**——用户只需把一段指令复制给 Agent |
| 并发 | 无（本地单用户） |

## 2. 用户场景（真实故事）

### 场景 A：刚确诊，想知道有什么治疗方向（U1）

> 老王 58 岁，确诊胰腺癌。家里人在网上查了一堆，越查越怕。
> 他儿子把青囊的部署指令复制给了自己的 Claude Code。

**青囊要做的**：Agent 自动判断这是「文献 + 试验 + 指南」三类混合问题，
并行调三条通道，给出一份带 PMID 与 NCT 编号的整理，并明确说「请与主治医生讨论」。

**不能做的**：说「建议你用 FOLFIRINOX」（触发红线 M1/M2）。

### 场景 B：想找能参加的试验（U2）

> 女儿想帮妈妈找国内正在招募的胰腺癌试验。

**青囊要做的**：调通道 4（统一试验检索，覆盖 ChiCTR + 中国登记平台 + CT.gov），
输出**登记号 + 分期 + 入组条件 + 中心医院 + PI + 状态 + 采集时间**。
按 `references/trials/report-outline.md` 七章提纲组织。

**不能做的**：说「你应该参加这个」（触发红线 M1）。
必须带采集时间（试验状态变化快）。

### 场景 C：看不懂报告单上的指标（U1）

> CA19-9 是 500，严重吗？

**青囊要做的**：说明「CA19-9 是肿瘤标志物，用于监测而非诊断」，
给出参考区间与影响因素，**引导问主治医生**。

**不能做的**：说「500 偏高，可能复发」（触发红线 M1）。

### 场景 D：报告单是 PDF，想整理归档（U2）

> 手上十几份报告单 PDF，想整理成能查的形式。

**青囊要做的**（Phase 3）：本地解析 → 指标抽取 → 存 `~/.qingnang/private/`。
**全程不联网**，不携带内容上传。

### 场景 E：社区志愿者想贡献一张知识卡（U3）

> 病友群的志愿者整理了一份「化疗期间饮食注意事项」。

**青囊要做的**：`CONTRIBUTING.md` 给出三步——建卡（用模板）→ 填 frontmatter → 提 PR。
自动闸门检查是否含真实患者信息；缺 `reviewed_by` 会提示。

### 场景 F：开发者想并入社区已有的 skill（U3）

> 社区里有个「临床试验情报推送」skill，挺好，能并进青囊吗？

**青囊要做的**：`MERGE_CONTRACT.md` 给出四条准入判据 + 三种合并方式。
Apache-2.0 → 方式 B（改进后并入），标注来源与改动。

## 3. 目标

### 3.1 产品目标（按优先级）

| # | 目标 | 为什么 | 可验证 |
|---|---|---|---|
| **G1** | **一键部署真的能一键** | 用户是病友不是工程师。部署失败 = 整个项目白做 | 干净环境复制指令跑一次 `exit 0` |
| **G2** | **Agent 第一次提问就命中正确通道** | 用户不知道"该用哪个工具"，Agent 也不该靠猜 | 六类典型问题各跑一次，通道选择与分流表一致 |
| **G3** | **零凭据可用** | 不能让"要申请 Key"成为门槛 | 不填任何 Key，五条通道可握手并返回结果 |
| **G4** | **医学红线不破** | 说错话的代价高于查不到 | 五条铁律可断言；急症/诊断/剂量三类必拦截 |
| **G5** | **病情数据不出机** | 病友最担心的事 | `private/` 隔离可执行断言；网络只发检索词 |
| **G6** | **社区能力可汇聚** | 单靠一个项目做不完，要靠社区 137 个仓库沉淀 | 准入四条 + 合并三种 + 双向引用耦合可断言 |
| **G7** | **失败可解释** | 用户不知道"为什么搜不到"就会放弃 | 降级必须可观察；`doctor.sh` 给中文修复指引 |

### 3.2 非目标（明确不做）

| # | 不做 | 为什么 |
|---|---|---|
| N1 | **不做诊断 / 给用药剂量** | 红线 M1/M2。这是产品定位，不是技术限制 |
| N2 | **不搜集所有社区仓库** | 只挑医学相关能力。137 个仓库里大部分是运营/基建工具 |
| N3 | **不做桌面发行版** | 属未来独立项目（ADR-006/ADR-012） |
| N4 | **不做 DSH 适配** | 同上。本包只留五条 forge 接缝 |
| N5 | **不引入服务端 / 云依赖** | 病友数据不出机的前提是数据不出本机 |
| N6 | **不做原生 Windows 脚本** | 首版要 Git Bash / WSL；原生支持属桌面端项目 |
| N7 | **不做医疗内容判断** | 只做检索路由与出处标注，不做医学结论 |

## 4. 成功标准（可度量）

### 4.1 硬指标（交付必须达成）

| # | 指标 | 判定方式 | 目标值 |
|---|---|---|---|
| **M1** | 一键部署成功率 | 干净环境按 README 指令跑 | **一次成功** |
| **M2** | 零凭据可用通道数 | `healthcheck.mjs` | **≥5 条**（共 7 条） |
| **M3** | 通道选择准确率 | 六类典型问题实测 | **6/6 一致** |
| **M4** | 医学红线拦截 | 构造急症/诊断/剂量三类提问 | **3/3 拦截** |
| **M5** | 隐私隔离 | `doctor.sh` + 断言 | **全部通过** |
| **M6** | Agent 首次可用时间 | 从拿到指令到第一次成功检索 | **≤10 分钟**（不含装包） |
| **M7** | 注入层体积 | `check.sh` | INJECT **≤2KB** / RUNTIME **≤8KB** |
| **M8** | 敏感信息闸 | `phi_scan.mjs` 正负向测试 | 真命中 / 假不误报 |

### 4.2 软指标（长期健康度）

| # | 指标 | 怎么看 |
|---|---|---|
| S1 | 社区贡献者数 | 有多少人提了知识卡 / 能力 |
| S2 | 病种扩展速度 | 新增一个病种子包需要多久 |
| S3 | 许可债清偿率 | `references/SOURCES.md` 的待办减少情况 |
| S4 | 上游同步成本 | 社区 skill 更新后，并入版能否跟上 |

### 4.3 反面指标（出现即视为失败）

| 现象 | 为什么是失败 |
|---|---|
| 用户报告「装不上」 | 违反 G1，整个项目的价值归零 |
| Agent 用通用搜索查临床指南 | 违反 G2，通道分流失效 |
| 出现"不需要 Key 就能用"被破坏 | 违反 G3，门槛回来 |
| 病友问「我是不是复发」，Agent 给了判断 | 违反 G4，**这是最严重的** |
| `private/` 里的东西出现在仓库里 | 违反 G5，事故级 |

## 10. 与母文档的关系

本 PRD **不推翻**母文档的愿景与架构，而是**收敛 + 校准**：

| 维度 | 母文档 | 本 PRD |
|---|---|---|
| 定位 | 资产包 + 桌面发行版（混在一起） | **只做资产包**；桌面发行版拆成未来独立项目 |
| 品牌 | 保留"未来可迁到中立 org" | **品牌 = 小胰宝**，不讨论中立 |
| 搜索通道 | 4 个 MCP | **7 条通道**（+web search / bing-cn / openalex / knows / get-biji） |
| skill 范围 | 未明确 | **合并 4 个社区 skill**（trials / guidelines 参考层） |
